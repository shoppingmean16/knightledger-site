# KnightLedger

A free, self-funded, not-for-profit civic quest board, repurposed on `feat/knightledger-quests`. The original `main`, production project and KnightLedger.com are preserved. This branch uses a separate Vercel project, private evidence store, and Postgres database.

## Run and review

Node 24. `npm ci`; copy `.env.example` to `.env.local`, configure secrets, then `npm run db:migrate`, `npm run dev`. `npm test`, `npm run typecheck`, `npm run lint`, `npm run build` are the checks. `node --experimental-strip-types --env-file=.env.local scripts/integration.ts` runs a production server and real SQL/HTTP integration checks in a disposable `qa-*` database namespace, then removes it. Self-hosted Cormorant Garamond and Inter fonts; original heraldic SVGs; Natural Earth public-domain geography. No analytics or external font calls.

Public pages: Quest Board `/`, quest details `/quests/:id`, Hall `/knights`, petitions `/petitions`, and private `/ledger`. Operator desk: `/steward`. Use the `OPERATOR_SECRET` from the staging project's Vercel environment settings; never send it through a URL or commit it. Operator access is separate from anonymous passports.

## Architecture and persistence

One Next.js App Router / TypeScript / Node app, one Neon Postgres database, private Vercel Blob, one configurable AI Gateway model and its supported web-search tool. Real search is performed at runtime, not through the builder's ChatGPT accounts. Public-source fetches use HTTPS, reject internal networks and raw IPs, pin resolved public addresses, bound redirects, size and time. No private LEGION brain or personal-account integrations are deployed.

Authoritative tables: `kl_localities`, `kl_members`, `kl_sessions`, `kl_quests`, `kl_petitions`, `kl_jobs`, `kl_completions`, `kl_chronicles`, `kl_prompts`, `kl_runs`, `kl_audits`, `kl_evidence`, `kl_meta`. These use typed application records in JSONB. A revision row and PostgreSQL `kl_commit` function serialize mutations using optimistic revision checks and a short row lock. Unique indexes enforce passport recovery digest, one completion per receipt, unique evidence/deed fingerprints, and one title per membership. Reads/writes currently load a small site's state; migrate to indexed per-record queries before sustained larger traffic. AI/network calls never hold a SQL transaction.

A submission is committed before background work starts. `after()` merely triggers work on an already durable database job. Scheduled reconciliation recovers pending jobs and expired leases. Jobs keep deadlines, attempts, source text, prompt version, reasons and outcomes. Retrieved source text is checkpointed before draft generation. Automatic retries are bounded to five attempts, with exponential delays; the operator can retry after fixing the issue. An expiring global AI lease prevents overlapping AI phases while publication and retention can proceed independently. Failures stay visible, never become fake approvals.

## Publication and knighthood

Board windows are 00:00 / 12:00 UTC. Requests received at least two hours before a window target it (equality included); later requests target the following window. Target time is fixed on the receipt. Missed deadlines are retained and marked; approval delays keep the prior board. Each valid distinct locality petition receives its own research job and linked quest. Same-member exact pending duplicates reuse their receipt. No population supply cap.

The owner reviews finished cards and approves all/selected, edits the full task and evidence instructions, returns for research, or declines with a reason. Return feedback is included in the next research attempt. Approval records the version and content hash. Draft edits retain prior content editions in the quest record. Source-only published editions are prepared as separate drafts; the old task remains live until owner-approved publication archives it, redirects its old URL, and preserves accepted-deed history. Substantive edits clear approval. Publication checks the exact hash, source recheck date and due time atomically. Initial Anywhere quests are authored seed content for this new preview; subsequent local quests require owner approval.

Proof is checked against each published standard by a bounded AI reviewer. Its exact recommendation and evidence snapshot are held for owner approval by default; progress cannot change before that approval. Proclamations are prepared and checked before the ceremony, then held for exact owner approval. A later edit invalidates that authority. Text-only proof is supported where proportionate. Accepted does not mean independently inspected. Code enforces ownership, duplicate deed/evidence prevention, frozen qualification targets and one title per passport.

Requirements freeze on first accepted completion: 3 accepted deeds for localities with <50 members with accepted work, 5 at 50–249, 7 at 250+. Separate useful repetitions of any quest count in full, including same-day work in the same locality; each must meet the whole standard with fresh evidence. There is no per-template or lifetime credit cap, and no locality Knight quota. This is the owner’s updated policy of October 25, 2026, replacing the original distinct-template and founding-place limits. One passport, one fixed home allocation, at most one knighthood. Complete eligible petitions are processed by submission time then receipt ID; service/budget delays carry forward, never become scarcity rejections. Sundays at 18:00 UTC, the Steward writes 150–250-word grounded proclamations, checkpoints them, independently checks factual grounding/privacy, and confers titles atomically; owner evidence and proclamation approval required at launch. The owner can later select automatic evidence/induction review independently in the private desk; the AI cannot change these settings. Quest publication always remains owner-approved. Interrupted or allowance-limited ceremonies retain eligible petitions for reconciliation, with the actual delay visible. No fake Knights are seeded.

## Scheduling and operation

`vercel.json` has separate once-daily routes for 03/09/15/21 research, 10/22 final preparation, 00/12 publication, daily retention, Sunday 18:00 induction and weekly prompt evaluation, and a daily health heartbeat at 13:35 UTC. The heartbeat makes unattended delivery observable independently of AI availability. All call one resumable worker and require `Authorization: Bearer CRON_SECRET`. Per-phase/day keys, expiring run/job leases, checkpoints, exact-version publication and duplicate-credit controls make retries safe. On Hobby each cron can run once daily, within the hour after its scheduled time (up to 59 minutes late). This cannot promise exact-minute updates. Cron activates on the isolated project's **production deployment**, not an ordinary branch preview; never point the original production domain to this project without approval.

Protected desk controls refresh prepared lists, pause/resume, publish approved due work, retry failed jobs, run retention, inspect windows, and restore validated prompts. Manual induction respects the weekly ceremony time. The operator's normal task is approval, not research or moving files.

Prompt v1 is preserved. At least three unused pieces of actual owner feedback are required for an appended writing/research refinement. Baseline and candidate generate outputs on four frozen synthetic cases. Evaluation is checkpointed across bounded runs. Deterministic grounding, locality, availability, evidence and safety checks plus an anonymized comparison must show no regression and at least one observable improvement before automatic promotion. A model rating its own prompt is insufficient. Rollback can restore a previously validated version. Prompt changes cannot change privacy, credentials, authority, approvals, spending or knighthood rules.

## Privacy and recovery

No required email, phone, real name, social login, address, GPS or tracking identifiers. Recovery codes contain 256 random bits; only SHA-256 digests are stored. Session cookies are HttpOnly, SameSite Strict and Secure on deployment. Recovery secrets never appear in URLs, logs or public projections. Losing the code can mean losing access. One passport is not proof of one human.

Evidence is private, at most three images of 1.2 MB, actual format checked and metadata stripped by Sharp. Authorized delivery checks ownership. Raw evidence expires 30 days after final decision or 60 days unresolved; unattached uploads expire after one day. A daily retention phase deletes files. Minimal accepted-deed summaries, completion dates and one-way evidence keys remain until deletion. Image/link hashes prevent evidence reuse after raw proof expires without retaining raw images or URLs. Text-only repeat proof is compared with recent accepted summaries by the bounded reviewer; anonymous accounts do not prove person-level uniqueness. Withdrawal/deletion removes membership, petitions, decisions and public chronicle; private files enter immediate deletion. Ordinary infrastructure logs/backups and AI processing are disclosed at `/privacy`. The map shows only public geographic centroids and aggregate counts; unverified places have a list fallback and no invented pin.

CSRF protection checks same-origin mutations; all inputs are bounded/validated; public rendering is escaped. Daily short-lived salted network digests limit anonymous recovery/enrollment abuse. Never log raw secrets, evidence or request bodies. Vercel SSO remains enabled.

## Configuration and cost boundaries

Required: `DATABASE_URL`, `BLOB_READ_WRITE_TOKEN`, `SESSION_SECRET`, `OPERATOR_SECRET`, `CRON_SECRET`. AI: `AI_GATEWAY_MODEL`, deployed Vercel OIDC identity (or `AI_GATEWAY_API_KEY` for local development). Optional: `MAX_AI_TASKS_PER_DAY` (12), `MAX_CYCLE_ITEMS` (3), `AI_PAUSED`, `KL_NAMESPACE`. Timing is configured in `vercel.json` together with the UTC window helpers in `lib/domain.ts` and the ceremony guard in `lib/worker.ts`; keep these in sync when changing schedules. Temporary database metadata: `NEON_DATABASE_EXPIRES_AT`, `NEON_PROJECT_ID`, `NEON_CLAIM_ASSERTION` (private; not used by public app).

No paid plan or purchased credits are authorized by this code. This preview uses a free claimable Neon database with a 72-hour expiration and small storage/transfer limits. The owner must claim it before expiry: sign in at the Steward desk and choose Prepare database claim link when ready. Continuing to Neon rotates database credentials, so update DATABASE_URL and redeploy afterward. Delete the obsolete NEON_CLAIM_ASSERTION after claim. Claim links expire quickly and are minted only when needed. Private Blob uses plan allowances. AI Gateway may require account payment verification to use free credit; lack of authorization is displayed and requests stay pending. No automatic credit purchase is configured.

Calls are bounded (12 daily, at most 3 items/cycle, output and time limits); this is a call cap, not a dollar-denominated hard billing cap. Set an account-level AI Gateway spend limit before opening unrestricted intake. Actual AI/search costs depend on the configured model/tool rates. No model call on page views. Vercel/Neon/Blob quota exhaustion pauses dependent flows; it must not be described as a working mock substitute.

## Release preflight and invited testing

The private desk now distinguishes configured credentials from verified provider access, runtime search/fetch, and an observed native heartbeat. `npm run release:check` is a read-only service preflight: it makes no AI calls, changes no configuration, and never approves, publishes or changes a domain. It fails on missing/short signing credentials, temporary database metadata, unverified/stale/different-model provider checks, absent runtime research, expired published source checks, missing recent heartbeat, non-owner launch review modes or an enabled invited-preview catalog. Passing these service checks does **not** replace end-to-end AI acceptance or the owner's deploy instruction.

AI connection failures are saved as concise operational checks. An unrelated successful phase cannot erase the public notice that research/review is delayed. Successful real search plus readable source retrieval is tracked separately from a successful model reply. No private diagnostic payload is projected publicly. Check live AI connection and the database claim control sit above the prepared quest list.

Returning an unpublished editorial/astronomy proposal now creates a durable revision job even without a member petition. LEGION re-reads the listed public sources, checkpoints them, and prepares a versioned, unapproved revision from the owner's comments. Unread citations are withheld. Source-only refreshes preserve the original task and successor version. The old published edition stays live. Failed jobs remain retryable; stale model callbacks cannot overwrite owner edits, a new return or a removal. Direct owner editing explicitly resolves the queued revision and still requires exact approval. Locality returns also reset exhausted attempts and invalidate old leases.

Rejected operator sign-ins and passport recovery attempts are now committed to the existing short-lived, salted abuse-limit records before checking credentials, so a failed lookup cannot roll back its own attempt. These records contain no raw IP, password or recovery code.
